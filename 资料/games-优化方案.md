# games 项目优化方案

> 仓库：`zhting/games` · 部署目标：`games.tangletang.top`
> 本文档基于对 `game/index.html`（软体求解器 `SoftBody.step` 与渲染管线 `drawJellyLoops` / `drawJellyLoops3D`）、`成语/index.html`、`lego/designs/lego-war/Lego War.html` 的完整代码审阅整理。

## 一、果冻俄罗斯方块（重点）

### 现状分析

当前实现为**轮廓质点链模型**：每条格边细分 3 段（`SUB = 3`），仅模拟边界顶点。受力构成：

| 力 | 参数 | 说明 |
|---|---|---|
| 形状保持弹簧 | `K_SHAPE = 110` | 顶点回复到静止形态位置 |
| 表面张力 | `K_SURF = 420` | 惩罚相对静止形态的曲率偏差 |
| 体积压强 | `K_PRESS = 3600` | 面积偏差沿外法线施压 |
| 全局阻尼 | `DAMP = 3.8` | 指数衰减 |
| 邻点相对阻尼 | 系数 `7` | 耗散高频微颤 |

每个物理子步（`PHYS_H = 1/180`）末尾执行"刚体平移抑制"，将整体钉回网格；另有 0.75 格形变钳制与速度钳制（`VMAX`）保证稳定。

该方案稳定性好，但与真实果冻存在几处本质差距，下面按"物理"与"视觉"两层给出改进方案。

### 1. 物理层：让它"抖"得像真果冻

#### 1.1 尺寸相关的振动频率 ⭐ 收益最大、改动最小

真实果冻的固有频率满足 **f ∝ √(G/ρ) / L**：越大块的果冻晃得越慢、越"duang"。当前 `K_SHAPE` 对所有块一视同仁，一格小块与四格 I 型块抖动频率完全相同，这是"塑料感"的主要来源。

**改法**：在 `build()` 时按包围盒尺寸缩放刚度：

```js
const k = K_SHAPE * (CS / Math.max(bw, bh));
```

或等价地给顶点赋予与面积成正比的质量。效果：大块慢晃、小块快颤，立刻产生果冻的"体量感"。

#### 1.2 降低全局阻尼，做频率选择性衰减

`DAMP = 3.8` 对应能量衰减时间约 0.26 秒；真实果冻被戳一下要晃 **1~2 秒（5~8 个可见振荡周期）**。

**改法**：
- 全局 `DAMP` 降至 **1.2 ~ 1.8**；
- 同时**加大**邻点相对阻尼（当前系数 7 → 提至 **12 ~ 15**）。

效果：高频微颤依然迅速平息（不会毛刺），但低频整体摇摆持久绵延——这正是果冻区别于橡胶的黏弹性特征。

**进阶**：增加 Maxwell 松弛项（弹簧串联阻尼器），模拟明胶的应力松弛——被持续压住一段时间后回弹力变弱。

#### 1.3 底部锚定，形成"悬臂摇摆"模态

真实果冻放在盘子上，底面被摩擦力粘住，晃动呈**顶部大幅摆、底部不动**的一阶剪切模态。当前的刚体平移抑制将全身平均位移归零，顶底摆幅对称，观感像悬浮的胶块。

**改法**：检测与格底/下方已锁定块接触的顶点，对其施加强切向摩擦（水平速度乘 0.2 ~ 0.4），并相应放松整体平移抑制强度。落地后的果冻将呈现经典的"底座不动、脑袋乱晃"。

#### 1.4 静态重力垂坠

真实果冻静止时并非完美方形——自重使其微微下塌、腰部外鼓。当前 rest 形态是精确的方格轮廓。

**改法**：在 `build()` 后对 rest 做一次性预变形——顶点按高度比例下移 2%~4%、底部外扩 1%~2%。`meltify()` 中已有现成的 sag 代码，取一个极小系数复用即可。所有静止方块都会带一点"憨态"。

#### 1.5 内部质点（中期改造）

只模拟轮廓意味着剪切波无法穿过体内，大块果冻形变不够"肉"。两条路线：

1. **内部弹簧格**：按格心布点，与轮廓点连弹簧，形成简易 FEM 网格；
2. **Shape Matching（推荐）**：采用 Müller 无网格形变——所有点向最优刚体/仿射拟合位置回弹。天然稳定、无需调弹簧网，还可顺手取消当前的 0.75 格形变钳制与速度钳制（这两个 clamp 在强冲击时会产生不自然的"撞墙"感）。

若走此路线，建议整体迁移到 **XPBD**（位置式动力学）：刚度与步长解耦，1/180 子步可放宽，性能反而更好。

#### 1.6 果冻之间的软接触与轻微黏连

当前块与块只靠 `nudgeAt` 传递一次性冲量，落在下方果冻上时下方不会被持续压扁。

**改法**：
- 在相邻已锁定块的接触边上互相施加持续的穿透排斥力（沿法线、按重叠深度），上方块的重量会持续压弯下方块的顶面；
- 分离时加一个很小的黏附力（拉伸 2~3 像素后断开），模拟明胶的微黏性。

消行时上方整片"坐"下来的瞬间会非常带感。

#### 1.7 撕裂（可发展为新玩法）

硬降冲击超过阈值时，真实果冻会裂开。可在应变超限顶点处把轮廓断开成两个 loop。在现有"融化 / 流体"模式框架下，这可以成为**第四种游戏模式**的核心机制。

### 2. 视觉层：让它"看"起来像真果冻

现有渲染已相当用心（折射、Beer-Lambert 边缘增浓、次表面散射、气泡视差），差距主要在 **"静态贴图感" vs "随形变而动的光学响应"**。

#### 2.1 让高光跟着形变跑 ⭐ 性价比最高

当前镜面光斑固定在包围盒左上 (32%, 20%) 的相对位置，果冻晃动时光斑纹丝不动，大脑立刻识破"这是贴图"。

**改法**：用 `centroidDelta()` 或顶部若干顶点的位移，反向偏移光斑位置，并按形变量拉伸/压扁光斑（表面凸起变化 → 高光位置与形状变化）。真实果冻最"活"的信号就是晃动时高光在表面上游走。

#### 2.2 折射随形变扰动

`refractFill` 目前是固定 1.16 倍放大。**改法**：将放大率与偏移量与当前形变挂钩——被压扁时放大率增大（透镜变厚）、倾斜时背景采样反向偏移。即使只做包围盒级别的近似（不做逐像素法线），晃动时背景在果冻里"荡漾"的效果也能出来。

#### 2.3 厚度相关的吸收

Beer-Lambert 目前用两圈固定宽度描边近似。**更真实的做法**：对轮廓做低分辨率距离场（SDF），按"到边缘的距离"映射颜色浓度——薄处（边缘、尖角）更透、厚处（中心）更浓，且随形变实时变化。Canvas 2D 下可用 8~12 像素粒度的离屏图计算，成本可控。

#### 2.4 焦散光斑

真实果冻下方桌面会有一个聚焦亮斑（凸透镜聚光）。在投影阴影内部叠一个小的 `screen` 混合亮椭圆，位置随果冻倾斜方向偏移——极便宜但辨识度极高的真实感线索。

#### 2.5 Fresnel 边缘增亮 + 轻微色散

掠射角处透明体反射率升高：沿轮廓法线背光侧加一条细的冷白描边（当前只有顶缘受光线）。进阶可在轮廓外缘错位叠 1px 的红/蓝描边模拟色散。

#### 2.6 终极路线：WebGL 片元着色器

将轮廓形变烘成法线/高度纹理传入 shader，即可实现真正的逐像素折射、Fresnel、粗糙镜面与厚度吸收。Canvas 2D 的上述近似能到 80 分，shader 能到 95 分。建议保留 Canvas 版作为降级方案。

### 3. 性能配套

上述改进会增加每帧成本，建议同步实施：

- 渐变对象按 `(颜色, 尺寸档位)` 缓存，避免每帧 `createLinearGradient`；
- 静止（sleeping）的果冻整层烘到一张离屏 canvas，只重绘活动块与被扰动块；
- 物理迁移 XPBD 后，子步从 1/180 放宽到 1/120。

## 二、成语守卫战

**数据层**
- `DB` 目前约几十对反义成语且硬编码在 HTML 中，建议拆为外部 JSON 并扩充到 **300+ 对**，按小学/初中/高中分难度档；
- 每次出牌命中后弹出该成语的释义小卡片，把"教育性"做实。

**玩法层**
- AI 出兵目前为定时器驱动，可按波次递增频率与卡牌质量，形成难度曲线；
- 增加"近义词混淆卡"作为干扰项，提升辨析难度。

**工程层**
- 加 `localStorage` 记录最高波次与已掌握成语，可扩展为"成语图鉴"收集系统；
- 补充移动端布局适配。

## 三、乐高战争

**离线收益（最关键）**
放置类游戏的核心预期是"关掉再打开有积累"，当前 `tickProduction` 只在页面打开时运行。在存档中记录 `lastTick` 时间戳，加载时按离线时长（建议封顶 8 小时）一次性补发资源。

**战斗表现**
战斗目前是即时结算，加一个 2~3 秒的简易战斗动画（双方兵力条互减）会大幅提升打击感。

**存档健壮性**
存档（`localStorage` 键 `legoWar2`）建议增加版本号字段与导出/导入功能，防止后续数据结构变更导致玩家存档损坏。

**字体依赖（实际 bug 级问题）**
`@import` 的 Google Fonts 在中国大陆无法访问，会阻塞渲染。目标用户显然是中文玩家，建议自托管字体文件或直接移除该依赖。
